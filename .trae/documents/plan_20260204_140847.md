# Implementation Plan for User Management & Data Safety System

This plan addresses your request for a Password Reset System (Task 11) and a Deletion Approval/Backup System (Task 12).

## 1. Password Reset & Management System (Task 11)

### Database Changes
*   **User Table:** Add `force_password_change` (Boolean) column.

### Admin Features (Settings > User Management)
*   Create a new **"User Management"** tab in Settings (visible only to Admins/Master).
*   **List Users:** View all registered users.
*   **Reset Password:** Admin can reset a user's password to a temporary default (e.g., `1234`).
    *   Action: Sets password to hash of `1234` and sets `force_password_change = True`.

### User Features (Login Flow)
*   **Forced Password Change:**
    *   Upon successful login, check if `force_password_change` is active.
    *   If active, block main entry and show a **"Change Password"** dialog.
    *   User must enter a new password to proceed.

## 2. Deletion Approval & Backup System (Task 12)

### Database Changes
*   **New Table `DeletionRequest`:**
    *   `requester_id`: User requesting deletion.
    *   `target_type`: Table name (e.g., 'formulations', 'production_runs').
    *   `target_id`: ID of the item.
    *   `reason`: User's reason for deletion.
    *   `status`: `Pending`, `Approved_Delete`, `Approved_Backup`, `Rejected`.
    *   `backup_data`: JSON field to store the full data snapshot (for backup).
    *   `admin_comment`: Admin's note.

### User Features (Request Deletion)
*   **Intercept Delete Action:**
    *   Modify "Delete" buttons in **Production History**, **Formulations**, etc.
    *   **Standard Users:** Instead of deleting, open a **"Deletion Request"** dialog requiring a reason.
    *   **Admins:** Option to "Delete Directly" or "Backup & Delete".

### Admin Features (Approval & Recovery)
*   **Deletion Request Manager:** A new interface to view pending requests.
    *   **Approve (Delete):** Permanently deletes the data.
    *   **Approve (Backup & Delete):** Serializes the data (including related items like recipe ingredients) to JSON, saves it to `backup_data`, then deletes the record.
    *   **Reject:** Cancels the request.
*   **Recovery Center:**
    *   View list of "Backed up" deletions.
    *   **Restore:** Re-inserts the data from JSON back into the active tables.

## 3. Execution Strategy
1.  **Database Update:** Update schema for `User` and create `DeletionRequest`.
2.  **Login Logic:** Implement the password change enforcement.
3.  **UI Implementation:**
    *   Add User Management to Settings.
    *   Add Deletion Request Dialogs to Document Management.
    *   Build the Admin Approval/Recovery Dashboard.
4.  **Serialization Logic:** Implement robust JSON backup/restore for complex data (Formulations with Items, etc.).
